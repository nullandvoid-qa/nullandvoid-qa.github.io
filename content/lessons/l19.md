<h2>Testes de API</h2>

<h3>🎯 Objetivos de Aprendizado</h3>
<ul>
  <li>Entender por que testes de API são obrigatórios para QA moderno.</li>
  <li>Conhecer as ferramentas mais usadas: Postman, REST Assured e Playwright APIRequest.</li>
  <li>Aprender os conceitos de contract testing e validação de schema.</li>
  <li>Escrever testes simples para endpoints REST baseados em dados reais.</li>
</ul>

<h3>🔍 Por que API é obrigatório?</h3>
<p>APIs são o núcleo da maioria dos sistemas modernos. Mesmo QA manual precisa validar se os dados entre frontend e backend batem e se as regras do serviço estão corretas.</p>

<ul>
  <li><strong>Rapidez:</strong> testar APIs é mais rápido que testar UI para grande parte da lógica.</li>
  <li><strong>Estabilidade:</strong> APIs mudam menos que interfaces visuais e são ideais para testes de regressão.</li>
  <li><strong>Visibilidade:</strong> permitem validar exatamente o que o backend retorna.</li>
</ul>

<h4>Famílias de Status Codes HTTP</h4>
<ul style="margin:1rem 0">
  <li>🟢 <strong>2xx (Sucesso):</strong> A requisição foi recebida e processada com sucesso (ex: 200 OK, 201 Created).</li>
  <li>🔵 <strong>3xx (Redirecionamento):</strong> Mais ações são necessárias para completar a requisição (ex: 301 Moved Permanently).</li>
  <li>🟡 <strong>4xx (Erro do Cliente):</strong> A requisição contém sintaxe incorreta ou não pôde ser processada (ex: 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found).</li>
  <li>🔴 <strong>5xx (Erro do Servidor):</strong> O servidor falhou ao tentar processar uma requisição válida (ex: 500 Internal Server Error, 503 Service Unavailable).</li>
</ul>

<h3>📬 Testes Manuais com Postman</h3>
<p>Postman é a ferramenta mais citada e útil para testes manuais e automação leve de API.</p>

<h4>🚀 Ponto de partida</h4>
<ol>
  <li>Crie uma nova coleção no Postman.</li>
  <li>Adicione um request GET.</li>
  <li>Defina a URL de testes.</li>
</ol>

<h4>📝 Exemplo Prático</h4>
<pre style="background:#f5f5f5; padding:1rem; border-radius:0.5rem; overflow-x:auto">
GET https://jsonplaceholder.typicode.com/posts/1
</pre>

<h4>✅ Verificação de resposta</h4>
<ul>
  <li>Status code esperado: `200`.</li>
  <li>Body deve conter o objeto JSON com os campos `id`, `userId`, `title` e `body`.</li>
  <li>Verifique headers importantes como `Content-Type: application/json; charset=utf-8`.</li>
</ul>

<h3>🧪 Postman Assertions</h3>
<pre style="background:#f5f5f5; padding:1rem; border-radius:0.5rem; overflow-x:auto">
pm.test("Status code is 200", function () {
  pm.response.to.have.status(200);
});

pm.test("Response has expected fields", function () {
  var jsonData = pm.response.json();
  pm.expect(jsonData).to.have.property("id", 1);
  pm.expect(jsonData).to.have.property("userId", 1);
  pm.expect(jsonData).to.have.property("title");
});
</pre>

<h3>☕ Automação com REST Assured (Java)</h3>
<p>REST Assured é uma biblioteca Java muito usada em vagas SDET e em times que já têm automação com Java.</p>
<pre style="background:#f5f5f5; padding:1rem; border-radius:0.5rem; overflow-x:auto">
import static io.restassured.RestAssured.*;
import static org.hamcrest.Matchers.*;
import org.testng.annotations.Test;

public class PostApiTest {
  @Test
  public void deveBuscarPostPorId() {
    given()
      .baseUri("https://jsonplaceholder.typicode.com")
      .pathParam("id", 1)
    .when()
      .get("/posts/{id}")
    .then()
      .statusCode(200)
      .body("id", equalTo(1))
      .body("userId", equalTo(1))
      .body("title", notNullValue());
  }
}
</pre>

<h3>🎭 Automação com Playwright APIRequest (JS/TS)</h3>
<p>Playwright também suporta testes de API com o módulo `APIRequest`, o que é útil para times que usam Playwright para UI e querem estender para backend.</p>
<pre style="background:#f5f5f5; padding:1rem; border-radius:0.5rem; overflow-x:auto">
const { test, expect } = require('@playwright/test');

test('API de posts retorna status e dados corretos', async ({ request }) => {
  const response = await request.get('https://jsonplaceholder.typicode.com/posts/1');
  expect(response.status()).toBe(200);
  const body = await response.json();
  expect(body.id).toBe(1);
  expect(body.userId).toBe(1);
  expect(body.title).toBeDefined();
});
</pre>

<h3>🤝 Contract Testing e Schema Validation</h3>
<p>Contract testing garante que o contrato entre serviços se mantenha estável. Schema validation valida que a resposta tem a estrutura esperada.</p>
<ul>
  <li>Postman: use `pm.response.to.have.jsonSchema(schema)` para validar a resposta.</li>
  <li>REST Assured: use `matchesJsonSchemaInClasspath("post-schema.json")`.</li>
  <li>Playwright: compare o JSON com um esquema ou use bibliotecas como `ajv`.</li>
</ul>

<pre style="background:#f5f5f5; padding:1rem; border-radius:0.5rem; overflow-x:auto">
const schema = {
  type: 'object',
  required: ['userId', 'id', 'title', 'body'],
  properties: {
    userId: { type: 'number' },
    id: { type: 'number' },
    title: { type: 'string' },
    body: { type: 'string' }
  }
};
</pre>

<h3>💡 Exemplos de Cenários de Teste de API</h3>
<ul>
  <li>GET id válido deve retornar 200 e dados corretos.</li>
  <li>GET id inexistente deve retornar 404 (ex: `/posts/999` ou `/posts/invalid`).</li>
  <li>POST com payload inválido deve retornar 400 Bad Request.</li>
  <li>Validação de contrato: campos obrigatórios existem e os tipos de dados estão corretos.</li>
</ul>
