<h2>Lógica e Programação Orientada a Objetos (POO) para QA</h2>

<h3>🎯 Objetivos de Aprendizado</h3>
<ul>
  <li>Compreender fundamentos úteis de programação para automação de testes.</li>
  <li>Aplicar conceitos básicos de POO para organizar automação (Pages, Helpers, Models).</li>
  <li>Escrever funções pequenas e testáveis em JavaScript/TypeScript e Python.</li>
  <li>Transformar requisitos em código de validação simples e reutilizável.</li>
</ul>

<h3>🔍 Por que programar ajuda o QA?</h3>
<p>Mesmo que você não seja desenvolvedor, programar permite: automatizar passos repetitivos, validar regras com precisão, gerar massa de testes e integrar verificações em pipelines.</p>

<h3>⚙️ Conceitos essenciais</h3>
<ul>
  <li><strong>Variáveis e tipos:</strong> números, strings, booleanos, arrays e objetos.</li>
  <li><strong>Estruturas de controle:</strong> if/else, loops (for/while) e operadores lógicos.</li>
  <li><strong>Funções:</strong> organizar comportamento em unidades reutilizáveis.</li>
  <li><strong>POO (básico):</strong> classes, construtores, métodos, herança e encapsulamento — úteis para organizar pages, componentes e helpers.</li>
</ul>

<h3>🧩 Exemplo simples: validação de entrada (JavaScript)</h3>
<pre style="background:#f5f5f5; padding:1rem; border-radius:0.5rem; overflow-x:auto">
function isValidEmail(email) {
  if (!email || typeof email !== 'string') return false;
  return /^[^@\s]+@[^@\s]+\.[^@\s]+$/.test(email);
}

module.exports = { isValidEmail };
</pre>

<h3>🧭 Exemplo POO: Page Object (TypeScript)</h3>
<pre style="background:#f5f5f5; padding:1rem; border-radius:0.5rem; overflow-x:auto">
export class LoginPage {
  constructor(private page) {}

  async goto() { await this.page.goto('/login'); }
  async login(username: string, password: string) {
    await this.page.fill('#user', username);
    await this.page.fill('#pass', password);
    await this.page.click('button[type=submit]');
  }
}
</pre>

<h3>🐍 Exemplo simples em Python (função testável)</h3>
<pre style="background:#f5f5f5; padding:1rem; border-radius:0.5rem; overflow-x:auto">
def normalize_phone(phone: str) -> str:
    digits = ''.join(c for c in phone if c.isdigit())
    if len(digits) == 11:
        return f"+55{digits}"
    return digits
</pre>

<h3>✅ Boas práticas para QA ao programar</h3>
<ul>
  <li>Escreva funções pequenas e com responsabilidade única (single responsibility).</li>
  <li>Separe lógica de seleção do DOM/elementos e lógica de verificação.</li>
  <li>Adote Page Objects ou helpers para evitar duplicação em testes UI.</li>
  <li>Escreva testes unitários para helpers críticos (validação de dados, conversões).</li>
  <li>Mantenha nomes claros para métodos e classes — isso facilita reprodução de bugs.</li>
</ul>

<h2>Lógica de Programação e POO para QA</h2>

<h3>🎯 Objetivos de Aprendizado</h3>
<ul>
  <li>Compreender a utilidade prática da Programação Orientada a Objetos (POO) em automação de testes.</li>
  <li>Entender os conceitos fundamentais de Classe, Objeto, Herança e Encapsulamento.</li>
  <li>Aprender a aplicar Herança para estruturar o padrão Page Object Model (POM).</li>
  <li>Reconhecer exemplos práticos estruturados em TypeScript e Python.</li>
</ul>

<h3>📊 Resumo Executivo</h3>
<p>Escrever testes automatizados não significa apenas "codificar passos". Para que as suítes de teste sejam sustentáveis e fáceis de manter, usamos o paradigma da <strong>Programação Orientada a Objetos (POO)</strong>. Ela nos ajuda a organizar o código de automação, evitar duplicação (DRY - Don't Repeat Yourself) e modelar elementos visuais como se fossem objetos reais do sistema.</p>

<h3>🏛️ Os 4 Pilares da POO Aplicados ao QA</h3>

<h4>1. Classes e Objetos</h4>
<p>A <strong>Classe</strong> funciona como um molde ou planta baixa de uma página ou componente (ex: a página de Login). O <strong>Objeto</strong> é a instância real desse molde criada na memória para executar ações.</p>
<pre style="background:#f5f5f5; padding:1rem; border-radius:0.5rem; overflow-x:auto">
// Exemplo em TypeScript: Definindo a classe LoginPage
class LoginPage {
  // Atributos (seletores de elementos na tela)
  usernameInput = '#username';
  passwordInput = '#password';
  submitButton = '#btn-submit';

  // Métodos (ações que podem ser feitas na tela)
  preencherLogin(usuario: string, senha: string) {
    console.log(`Digitando usuario: ${usuario} e senha.`);
  }
}

// Criando um Objeto (Instanciando a classe)
const login = new LoginPage();
login.preencherLogin("ana@email.com", "senha123");
</pre>

<h4>2. Herança (Inheritance)</h4>
<p>Permite que uma classe filha herde atributos e métodos de uma classe pai. Na automação de testes, é extremamente comum termos uma classe pai chamada <code>BasePage</code> (que contém métodos comuns como navegar, clicar e tirar screenshots) e páginas específicas que herdam essas capacidades.</p>
<pre style="background:#f5f5f5; padding:1rem; border-radius:0.5rem; overflow-x:auto">
// Classe Pai (BasePage)
class BasePage {
  baseUrl = "https://meusite.com";

  navegar(urlPath: string) {
    console.log(`Navegando para: ${this.baseUrl}${urlPath}`);
  }

  tirarPrint() {
    console.log("Screenshot capturada com sucesso.");
  }
}

// Classe Filha (LoginPage herda de BasePage)
class LoginPage extends BasePage {
  inputEmail = "#email";

  realizarLogin() {
    this.navegar("/login"); // Herdado de BasePage
    this.tirarPrint();      // Herdado de BasePage
  }
}
</pre>

<h4>3. Encapsulamento</h4>
<p>Consiste em "esconder" os detalhes internos de como a classe funciona e expor apenas métodos limpos e seguros. Na automação, isso impede que os scripts de teste acessem diretamente seletores frágeis ou executem ações fora de ordem.</p>
<pre style="background:#f5f5f5; padding:1rem; border-radius:0.5rem; overflow-x:auto">
class CheckoutPage {
  // Seletores privados (encapsulados, inacessíveis fora da classe)
  private inputCartao = "#card-number";
  private btnFinalizar = "#pay-btn";

  // Método público exposto para o teste
  public pagarComCartao(numeroCartao: string) {
    this.preencherCartao(numeroCartao);
    this.clicarPagar();
  }

  private preencherCartao(numero: string) { /* lógica */ }
  private clicarPagar() { /* lógica */ }
}
</pre>

<h3>🐍 Exemplo Prático em Python (Page Object Model)</h3>
<p>Abaixo está um exemplo de como estruturar testes usando POO com Python e a biblioteca Selenium ou Playwright:</p>
<pre style="background:#f5f5f5; padding:1rem; border-radius:0.5rem; overflow-x:auto">
# base_page.py
class BasePage:
    def __init__(self, driver):
        self.driver = driver

    def navigate_to(self, url):
        self.driver.get(url)

# login_page.py (herda de BasePage)
from base_page import BasePage

class LoginPage(BasePage):
    def __init__(self, driver):
        super().__init__(driver)  # Chama o construtor do pai
        self.username_field = "username"
        self.password_field = "password"
        self.login_button = "login-btn"

    def login_with(self, username, password):
        self.driver.find_element_by_id(self.username_field).send_keys(username)
        self.driver.find_element_by_id(self.password_field).send_keys(password)
        self.driver.find_element_by_id(self.login_button).click()
</pre>

<h3>💡 Por que usar POO reduz custo de manutenção?</h3>
<p>Se o ID do botão "Pagar" mudar de <code>#pay-btn</code> para <code>#checkout-confirm-btn</code>, você só precisará atualizar essa string em <strong>um único lugar</strong>: dentro da classe <code>CheckoutPage</code>. Nenhum de seus 50 arquivos de testes automatizados precisará ser alterado.</p>
